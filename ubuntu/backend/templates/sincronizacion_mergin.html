Sincronizacion Mergin

Conecta un PostgreSQL local, selecciona un schema existente compatible con LADM-COL y analiza el ZIP retornado desde campo antes de habilitar la sincronizacion.

Fase activa 1, 2 y 3
1 Configuracion local
2 Destino
3 Proyecto Mergin
4 Sincronizacion

Paso 1. Configuracion PostgreSQL local

La conexion se usa solo para este flujo y no depende de tenants ni de configuracion productiva.

Configura las credenciales y ejecuta la prueba.

Paso 2. Seleccion de destino

Despues de conectar, selecciona la base local y el schema destino ya creado mediante LADM-COL.

Aun no se han cargado schemas.

Schemas detectados

Se marca compatibilidad con base en la presencia de tablas base de workspace LADM-COL/Arbimaps.

Schema Compatibilidad Tablas clave Detalle
Conecta una base local para listar schemas compatibles.

Paso 3. Analisis del archivo ZIP

Se extraen todos los GPKG del proyecto Mergin y se clasifica cada capa segun la whitelist de Fase 3, sin importar datos.

Selecciona un ZIP de Mergin para iniciar el analisis.

Paso 4. Importacion a schema temporal

La importacion se limita al schema staging. El schema destino solo se valida y nunca se modifica en esta fase.

Analiza el ZIP y define el schema staging antes de ejecutar la simulacion o la importacion.

Paso 5. ETL staging hacia schema destino

Se transfieren solo tablas operativas desde el staging hacia el schema oficial seleccionado, respetando llaves, constraints y dominios del target.

Ejecuta primero la importacion a staging y luego simula la transferencia antes de aplicar.
